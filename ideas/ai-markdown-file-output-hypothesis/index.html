让 AI 写成 Markdown 文件，回答会变长吗？

一个关于 AI 网页、文件生成、输出长度和"智能体感"的实验。

这个想法从哪里来

我最开始的直觉很简单：当我让 AI 把答案写成一个可下载的 Markdown 文件，而不是直接在聊天框里输出时，它好像突然认真了很多，写得也长了很多。但这个直觉可能是错的，也可能只在某些产品里成立。所以这个页面不是结论，而是一组实验的起点。

我观察到，在某些 AI 网页产品中，直接让 AI 在聊天窗口回答时，回答可能相对短；但如果要求它生成一个文件，输出可能突然变得非常长——数千字、结构完整、像报告一样的内容。这个现象可能说明：

  • 网页聊天回答和文件生成回答不是同一种产品路径；
  • 同一个模型在不同 UI / 工具中可能表现不同；
  • "让 AI 生成文件"可能会触发一种更偏向"文档生产"的模式。

核心假设

H1：文件化输出增长假设

对同一个任务、同一个 AI 网站、同一个模型，要求"把最终输出写成一个可下载的 Markdown 文件"时，输出长度可能显著高于普通聊天回答。显著 = 字符数 ≥ 1.5 倍，或结构明显更完整。

H2：质量结构假设

文件化输出不只可能更长，也可能更像正式文档：标题、目录、章节、表格、步骤、结论等会更完整。但需单独评估，不能直接用字数替代质量。

H3：智能体能力信号假设

如果一个 AI 网页可以生成可下载文件、编辑文件、生成多文件结构，那么它可能接入了工具执行、文档生成或智能体式能力。这是一个外部行为判断。

实验设计

对多个 AI 网站进行同题测试，比较 5 种提示方式的输出差异：

  • A 组：普通聊天回答（基线）
  • B 组：Markdown 格式回答（测试格式本身的作用）
  • C 组：要求生成 Markdown 文件
  • D 组：要求可下载 Markdown 文件（强调下载）
  • E 组：文档工作区 / Artifact / Canvas（如产品支持）

每个条件至少重复 3 次。同一网站使用同一模型。保留原始输出。记录是否真的生成文件。单独评估字数和质量。

质量评分规则

每次输出按 7 个维度评分（每项 1-5 分，最高 35 分）：

  • 完整性 — 是否覆盖问题的主要方面？
  • 结构性 — 是否有清晰层级、章节、总结？
  • 具体性 — 是否有具体例子、步骤、判断标准？
  • 准确性 — 是否有明显错误或胡编？
  • 可执行性 — 是否能拿去直接用？
  • 克制性 — 是否承认不确定性和边界？
  • 信息密度 — 是否不是单纯堆字数？
